5 small UI/UX
things.

Lessons picked up in code reviews at Frappe. Each one is tiny. Together they make a big difference.

  1. 01

    Don’t disable the button.
    Tell them why.

    A greyed-out action leaves people guessing. Keep it enabled, and on click say exactly what they need to do.

    Don’t
    main ▾
    Switch branch
    Do
    main ▾
    Switch branch Pick a different branch
  2. 02

    One primary action
    per view.

    Ask what the person is here to do. That gets the primary button. Everything else is secondary or tertiary.

    Don’t
    VisitUpdateLogin
    Do
    VisitLoginUpdate
  3. 03

    Cut redundant labels.

    Proximity already gives the context. If you are inside “Manage Event”, the tabs don’t need to say “Manage” again.

    Don’t
    Manage EventManage RSVPManage TicketsDownload Attendee List
    Do
    Manage EventOverviewTicketsAttendees  ↓
  4. 04

    Monospace for
    fixed-length strings.

    Commit hashes, IDs, codes: same number of characters, same width. The column lines up on its own.

    Don’t
    v15a1b2c3d
    v141f1i7l1
    v13w4mw0e2
    Do
    v15a1b2c3d
    v141f1i7l1
    v13w4mw0e2
  5. 05

    Never break
    aspect ratios.

    Lock proportions when you resize, and style images to survive any size a CMS throws at them.

    The biggest crime against humanity. — Rushabh
    Don’t
    Do
    aspect-ratio: 1 / 1;

Tricks like these aren’t taught in college. We learn them by building in the wild and asking for feedback.
